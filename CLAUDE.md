## Project Overview

**Prehistoric Hunter** — 4-player cooperative dinosaur hunting game for a dinosaur-themed bar. Built with Phaser 3 + Vite. Source lives in `src/` (referenced by `index.html`), tests in `tests/`, assets in `assets/`.

All player-facing text must be in **German**.

## Development Commands

```bash
npm run dev              # Start dev server (Vite)
npm test                 # Run tests (Vitest)
npm run build            # Production build
npm run build:spritesheets  # Pack animation frames into Phaser atlas files
```

Run a single test file: `npx vitest tests/Player.test.js`

## Architecture

### Game Structure

- `src/main.js` — Entry point; bootstraps Phaser
- `src/scenes/` — Phaser scenes (hunt, cave bar, transitions)
- `src/entities/` — Game objects: `Player`, dinosaurs, etc.
- `src/systems/` — Core systems: `SessionManager`, `InputManager`, `PhysicsManager`, `CameraController`, `CombatSystem`

Key system relationships:
- `SessionManager` persists player state (upgrades, score, health) across hunt→cave bar→hunt cycles
- `InputManager` handles both keyboard (WASD/SHIFT/click) and gamepad input
- `CombatSystem` owns weak-point targeting, dodge rolls, and projectile logic

### Asset Pipeline

Assets are generated by AI tools, then packed into Phaser atlases:

```
assets/spritecook/         # Raw AI-generated frames (WebP animations)
  animations/{hero}/       # Per-hero animation clips (east + south directions)
  enemies/{dino}/          # Enemy animation clips
  stills/                  # Weapon still images (approval gate — see below)
  manifest.json            # Maps animation keys → SpriteCook asset IDs + file paths

scripts/build-spritesheets.js   # Packs frames → assets/generated/spritesheets/
scripts/image_gen.py            # OpenAI image generation CLI (generate / generate-batch / edit)
```

SpriteCook animated `.webp` files are converted with `npm run build:spritesheets` into combined entity atlases under `assets/generated/spritecook/entities/`, with a generated summary at `assets/generated/spritecook/manifest.json`.

If work changes `assets/spritecook/` or `assets/spritecook/manifest.json`, rerun `npm run build:spritesheets` before handoff. Check the generated manifest for skipped source files when an expected animation is missing.

### SpriteCook Workflow

**Weapon stills approval gate:** After generating weapon stills for a new hero, pause and show them to the user before generating weapon animations. See `docs/plans/spritecook-animation-plan.md` for the full animation matrix.

Attack animation rules:
- Always use `edge_margin=25` (max) for attack animations
- Always use `auto_enhance_prompt=false` — auto-enhance causes weapons to disappear mid-animation
- Minimum 6 frames for attacks

## Landing the Plane (Session Completion)

**When ending a work session**, you MUST complete ALL steps below. Work is NOT complete until `git push` succeeds.

**MANDATORY WORKFLOW:**

1. **File issues for remaining work** - Create issues for anything that needs follow-up
2. **Run quality gates** (if code changed) - Tests, linters, builds
3. **Update issue status** - Close finished work, update in-progress items
4. **PUSH TO REMOTE** - This is MANDATORY:
   ```bash
   git pull --rebase
   bd sync
   git push
   git status  # MUST show "up to date with origin"
   ```
5. **Clean up** - Clear stashes, prune remote branches
6. **Verify** - All changes committed AND pushed
7. **Hand off** - Provide context for next session

**CRITICAL RULES:**
- Work is NOT complete until `git push` succeeds
- NEVER stop before pushing - that leaves work stranded locally
- NEVER say "ready to push when you are" - YOU must push
- If push fails, resolve and retry until it succeeds

## Golden Rule

**Always prefix commands with `rtk`**. If RTK has a dedicated filter, it uses it. If not, it passes through unchanged. This means RTK is always safe to use.

**Important**: Even in command chains with `&&`, use `rtk`:
```bash
# ❌ Wrong
git add . && git commit -m "msg" && git push

# ✅ Correct
rtk git add . && rtk git commit -m "msg" && rtk git push
```
